How it works

From reference to agent-built site.

Site Stripper maps a public URL, extracts its visual DNA, and makes the evidence available to your coding agent through local MCP tools. Download the comprehensive ZIP when you prefer a manual handoff.

Connect an agent Explore the sample pack
01 · DISCOVER

Choose a public site

Start with an HTTP or HTTPS URL. The analyzer validates the target, then looks for useful same-site pages through public navigation, links, and site-map signals.

02 · OBSERVE

Map pages and design details

Pages are examined one at a time for headings, visible content, layout, design tokens, controls, media references, responsive behavior, and available captures.

03 · ORGANIZE

Review the reference pack

Bounded observations are rendered into page notes, cross-page guides, and machine-readable files. Coverage notes keep partial results and known limits visible.

04 · CONNECT

Build from the evidence

Connect your local MCP-compatible agent to request analysis and page details directly. The ZIP and copyable prompt are available for a manual handoff; captures are included when available.

Turn reference details into a new website.

The ZIP gives an AI coding agent a clear starting point for the reference site's visual DNA. Page notes explain what appears and in what order. Design tokens, responsive observations, and captures add the detail needed to carry the same style and art direction into a brand-new site or web app.

Choose your agentConnect Claude Code, Codex, OpenCode, Cursor, and any other AI agent that supports MCP. Agents without MCP can read the ZIP directly.

Observed page details

Each note stays linked to its source page.

Headings, visible text, navigation, media references, and layout samples are recorded alongside the page where they were observed. That makes it easier to move from a package summary to specific source details.

  • Page-level notes preserve content order.
  • Structured records keep the same details available as data.
  • Capture files appear when a screenshot completes successfully.

Page selection

Review which pages were included and why.

Each run records the candidates it considered and the pages it inspected.

From candidate pages to the selected set

Page candidates come from public site structure and are ranked for relevance. The selection report records which pages were included and the reason for each decision. This makes the scope of a run easy to review.

Discovery sourcesSite-map entries, primary navigation, and relevant same-site links help build the candidate list.
Page-specific notesWritten notes keep headings, content, and section order tied to the page they describe.
Coverage dataSelection and report files show what was analyzed and where a run reached its limits.

Hosted run limits

One hosted run can analyze up to 10 selected pages in up to 150 seconds. Browser time and screenshot capacity are bounded, so a slow or media-heavy source may return partial results. The report makes those limits visible instead of implying complete coverage.

One page at a time

The analysis uses a single browser session and processes pages sequentially. This keeps the run focused and allows the report to associate each observation and capture with its source page.

After observations return, the browser-side package builder renders the guides and structured records, validates the file set, and creates the downloadable archive.

What the observations mean

The pack describes what the analyzer could observe at capture time. It is evidence for a separate rebuild workflow, not an offline copy of the source website.

  • Source-site forms are not submitted.
  • CAPTCHA and bot-verification challenges are not bypassed.
  • Arbitrary JavaScript interactions are not replayed.
  • Screenshot files appear only when captures succeed and fit the run limits.

Agent integrations

Let your agent ask for the evidence.

Site Stripper exposes a local MCP endpoint while the local workspace is running. It lets Claude Code, Codex, OpenCode, Cursor, and any other AI agent that supports MCP request an analysis and focused page evidence without copying each observation into chat.

01 · CONNECT

Choose an MCP client

Open Agent connections in the local workspace, select your client, and copy the endpoint configuration. The workspace fills in the port it is using.

http://127.0.0.1:<local-port>/mcp

Setup guides: Claude Code, Codex, Cursor, and OpenCode.

02 · REQUEST

Ask for focused evidence

Your agent can start an analysis, request a compact Visual DNA profile, inspect one page at a time, or retrieve the generated build brief.

analyze_public_siteget_visual_dnaget_page_evidenceget_rebuild_brief

03 · BUILD

Recreate the visual language

The connected agent uses its own model and provider to interpret the evidence and build in its project. Site Stripper does not call a model API.

The provider may process page text and design observations returned to the agent under its own account settings and policies.
